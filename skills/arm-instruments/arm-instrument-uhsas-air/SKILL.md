# UHSAS-AIR - Ultra-High Sensitivity Aerosol Spectrometer aboard aircraft

The UHSAS is an optical-scattering, laser-based aerosol particle spectrometer that sizes and counts particles in the 60- to 1000-nm range, deployed aboard aircraft (canister version on the Gulfstream-1 wing pre-2017, bench version in-cabin thereafter) to measure aerosol particle number size distributions.

## How it measures

Aerosol particles are drawn into the instrument's optical chamber and pass in front of a laser beam. The instrument's infrared (1054-nm) laser illuminates the particles, which scatter light, and four optical detectors capture the light signals generated by particles passing through the laser beam, collected in a direction perpendicular to both the particle flow and the laser beam. These peak light signals are used for particle sizing, since the amount of light scattered correlates strongly with particle size. The instrument counts particles in up to 100 user-specified sizing bins, producing an equivalent optical diameter distribution as particle number concentrations per bin.

**Siting.** For campaigns previous to 2017, deployed as a canister version on board the Gulfstream-1 aircraft on the starboard wing; replaced for campaigns after 2017 with a bench version placed in the cabin with modified volumetric air flow control to compensate for changing cabin pressure and sampling pressure. During CACTI, the sheath flow valve was replaced by a volumetric flow controller aboard the Gulfstream-159.

**Sampling.** native rate 1 Hz (typically every second in flight); reported every every second in flight; averaging sample accumulation time is user-specified (hb p. 3).

## Getting the data

ARM Live needs `ARMUSER` / `ARMTOKEN` credentials; see the `act-arm-live` skill for the
service, datastream naming and the server-side subset endpoint.

The `act-arm-live` and `act-qc` skills wrap these calls in shorter helpers
(`armlive_open`, `armlive_list_files`, `act_qc_table`, `act_qc_apply`). Those are helpers
those skills define, **not** ACT functions - nothing below uses them, so every block here
runs against a bare `act-atmos` install.

```python
import os, requests, act

user, token = os.environ["ARMUSER"], os.environ["ARMTOKEN"]

# ACT has no list-only call, so size the request against ARM Live's query endpoint
# before transferring anything.
avail = requests.get("https://adc.arm.gov/armlive/livedata/query",
                     params={"user": f"{user}:{token}", "ds": "sgpaafuhsasF1.b1",
                             "start": "2016-09-21", "end": "2016-09-21", "wt": "json"}).json()
print(avail["num_found"], avail["total_size"])            # files, bytes

# Downloads into ./sgpaafuhsasF1.b1/ unless you pass output=
files = act.discovery.download_arm_data(user, token, "sgpaafuhsasF1.b1", "2016-09-21", "2016-09-21")
assert files, "nothing transferred - ARM Live rate limits with HTTP 429; retry"
ds = act.io.arm.read_arm_netcdf(files, cleanup_qc=True)
print(act.discovery.get_arm_doi("sgpaafuhsasF1.b1", "2016-09-21", "2016-09-21"))   # cite what you pulled
```

## Quality control in this datastream

8 `qc_` companion variables cover 8 of the
28 data variables. Assessments present in the example file: `Bad`, `Indeterminate`.

`cleanup_qc=True` on read is what makes these usable - it rewrites ARM's flag
attributes into the form `qcfilter` expects. Remember that ARM uses two assessment vocabularies - `Bad`/`Indeterminate`
from the automated tests, `Incorrect`/`Suspect` after DQR normalisation - and that
filtering on only one of them silently keeps known-bad points.

```python
# What each test would remove, one variable at a time
print(ds["qc_size_distribution"].attrs.get("flag_meanings", "no flag_meanings"))
mask = ds.qcfilter.get_masked_data("size_distribution", rm_assessments=["Bad", "Indeterminate"],
                                  return_mask_only=True)
print(int(mask.sum()), "of", mask.size, "points flagged")

# NaN-fill in place. ARM b1 files use Bad/Indeterminate, VAPs often use
# Incorrect/Suspect - pass every name you might meet.
ds.qcfilter.datafilter(variables=["size_distribution", "total_number_concentration", "sample_flow_rate"],
                       rm_assessments=["Bad", "Indeterminate", "Incorrect", "Suspect"],
                       del_qc_var=False)
```

The handbook's own note on data quality: Data quality evaluation involves automatic generation of plots in collaboration with the ARM Data Quality Office: aerosol particle size distribution vs. time (checking for low counts/noisy signal indicating optics or flow issues); comparison of UHSAS total particle number concentration with co-located CPC or SMPS (UHSAS should follow same trend but show lower concentration due to higher lower-size-limit); sample flow rate (low/unstable indicates blockage or failing pump); laser reference voltage (more than 25% below nominal 2.5 V indicates dirty optics or misalignment). ## Known artifacts and failure modes

From the handbook. This is the section to read before concluding that a feature in
the data is atmospheric.

| issue | how it shows up | what the handbook says to do | source |
|---|---|---|---|
| Low counts or noisy signal from UHSAS optics block issues (misalignment, contamination)... | Aerosol particle size distribution as a function of time shows low counts or noisy signal | Reviewed via automatic DQ plots in collaboration with ARM Data Quality Office | (hb p. 6) |
| UHSAS reports lower total concentration than co-located CPC or SMPS | Comparison plots show UHSAS following the same general trend as CPC/SMPS but at lower concentration | Expected because the lower particle size limit for UHSAS is higher than for CPC or SMPS | (hb p. 6) |
| Low or unstable sample flow rate | Sample flow rate housekeeping data shows low or unstable values | Indicates a blockage in the sample line or a failing pump | (hb p. 6) |
| Dirty optics or misaligned optical elements | Laser reference voltage more than 25% lower than nominal value of 2.5 V | Clean laser optics per manufacturer's manual when voltage falls below ~1.9 V | (hb p. 6) |
| Decreased counting confidence below 100 nm due to decreased detection efficiency | Particle counts below 100 nm size bin appear as lower bound estimates | Treat as lower bound estimation; be critical of particles smaller than 100 nm | (hb p. 7) |
| Sizing inaccuracy for non-spherical particles or particles with refractive index... | Measured particle size differs from true size when ambient aerosol shape/refractive index differs from PSL | If ambient particle refractive index is known, corrections can be applied to the measurement data | (hb p. 7) |
| Particle coincidence at high concentrations | Sizing/counting accuracy and repeatability specs (5% accuracy, 1% repeatability) only valid below 3000 s-1; above this, coincidence causes undercounting/mis-sizing | No corrections for particle coincidence are made; use a dilution system when sampling above the upper concentration limit of ~3000 s-1 (3600 cm-3 for... | (hb p. 8) |
| Sheath flow mass flow controller inadequate on airborne platforms due to inverse... | Biased pulse width measurement caused by changing particle velocity through the laser beam with altitude/pressure changes | Corrected in multiple flight campaigns by replacing the sheath flow valve with a volumetric flow controller to directly monitor and control sheath... | (hb p. 10) |
| Needle-valve sheath flow control is pressure/Reynolds-number dependent | Changing pressures vary the sheath-sample flow ratio because pressure drop through the valve is Reynolds number-dependent | Replaced with volumetric flow controller in modified instrument (used for CACTI) | (hb p. 10) |
| No corrections applied from calibration verification checks | Calibration check data show drift/mismatch but data are not adjusted retroactively | Instrument is size-calibrated by mentors or sent to manufacturer for maintenance if verification fails | (hb p. 7) |


## Calibration and maintenance

|  |  |
|---|---|
| Calibration method | Manufacturer calibration: measuring size distribution of NIST-traceable PSL calibration aerosols with known mean particle sizes; calibrating gain of four internal pulse-height measurement ranges; calibrating inlet flow rate with a precision flow meter; zero counts verification using a HEPA filter on the inlet. Mentor... (hb p. 11) |
| Calibration interval | typically once every 12 months or as needed, e.g., before deployment (hb p. 11) |
| Traceability | NIST-traceable PSL calibration aerosols (hb p. 11) |
| Routine maintenance | Cleaning the laser optics when laser reference voltage falls below ~1.9 V; consult the manufacturer's manual for procedure (hb p. 12) |
| Maintenance interval | as needed (triggered by low laser reference voltage) (hb p. 12) |


Calibration history matters for trend work: a step at a calibration date is an
instrument event, not a climate signal.
