# TBSGROUND - Tethered Balloon System Ground Measurement

The tbsground subsystem uses surface-based anemometer, temperature/relative humidity probe, and barometer sensors at the ARM TBS ground station to collect continuous, once-per-second surface observations of wind speed, gust wind speed, temperature, relative humidity, and pressure, which are reported as 1-minute averages.

## How it measures

The tbsground datastream is generated by an NRG Systems IceFree3 heated anemometer, a Campbell Scientific EE181 temperature and relative humidity probe, and a Campbell Scientific CS100 barometer mounted at the ARM TBS ground station. These sensors collect continuous, surface-based observations of wind speed, gust wind speed, temperature, relative humidity, and pressure once a second. One-second data is averaged over one minute in tbsground output variables, except for wind_speed_max, which is the maximum one-second gust speed recorded within one minute. Unlike other TBS datastreams that are only created when the TBS is in flight, tbsground is continuously collected at the surface during TBS deployments.

**Siting.** Measurements are collected from the anemometer at approximately 4 m above the surface, from the temperature and relative humidity sensor approximately 2 m above the surface, and from the pressure sensor approximately 1 m above the surface. The TBS is generally operated with a collocated ceilometer to provide cloud base and mixing layer heights, but the ceilometer is currently operated independently from the TBS ground station. It is advantageous for the TBS to operate near a Doppler lidar, but ARM Doppler lidars are operated independently of the TBS and TBS operations do not typically require an adjacent Doppler lidar; if dedicated to TBS flight operations, a Doppler lidar is operated in a...

**Sampling.** native rate 1 Hz (once per second); reported every 1 minute; averaging One-second data is averaged over one minute in tbsground output variables except for wind_speed_max, which is the maximum one-second gust speed recorded within one minute. (hb p. 8).

import act

## Quality control in this datastream

12 `qc_` companion variables cover 12 of the
34 data variables. Assessments present in the example file: `Bad`.

`cleanup_qc=True` on read is what makes these usable; then screen with the `act-qc`
helpers. Remember that ARM uses two assessment vocabularies - `Bad`/`Indeterminate`
from the automated tests, `Incorrect`/`Suspect` after DQR normalisation - and that
filtering on only one of them silently keeps known-bad points.

```python
act_qc_table(ds)                       # what each bit would remove, per variable
act_qc_apply(ds, variables=[...])      # NaN-fill using all four assessment names
```

On the example file no test fired on any variable, so the flag machinery is
present but unexercised there - do not read that as a guarantee for other days.

Either way, check the DQRs before trusting a period - they carry the mentor's knowledge
of icing, misalignment and outages that no automated test catches:

```python
act.qc.print_dqr("sgptbsgroundC1.b1", "20160418", "20260924")
```

The handbook's own note on data quality: Each datastream, including tbsground, includes quality control variables for each scientific variable.

## Known artifacts and failure modes

From the handbook. This is the section to read before concluding that a feature in
the data is atmospheric.

| issue | how it shows up | what the handbook says to do | source |
|---|---|---|---|
| Continuous vs. flight-only data coverage | tbsground datastream shows continuous surface data throughout a TBS deployment, while other TBS datastreams (e.g., tbscpc, tbspops, tbswind) show data only during flight periods, causing... | None stated beyond noting the distinction. | (hb p. 18) |
| 1-minute averaging smooths short-term variability | wind_speed and other tbsground variables reflect 1-minute averages of 1-second samples, so short-duration gusts or fluctuations are smoothed out except for wind_speed_max, which retains the... | wind_speed_max variable is provided separately to capture peak 1-second gust within each minute. | (hb p. 8) |
| Differing sensor heights above surface | Wind, temperature/RH, and pressure measurements are collected at different heights above the surface (approximately 4 m, 2 m, and 1 m respectively), which can introduce apparent... | None stated beyond documenting the respective heights. | (hb p. 8) |
| Ceilometer and Doppler lidar operated independently of TBS | Cloud base and mixing layer height or wind profile data from a collocated ceilometer/Doppler lidar are not part of the tbsground datastream itself and must be obtained/matched separately;... | None stated; ceilometer/lidar data are separate systems that may need to be merged (see tbsmerged). | (hb p. 8) |
