# UHSAS - Ultra-High Sensitivity Aerosol Spectrometer

The UHSAS is an optical-scattering, laser-based aerosol particle spectrometer that measures particle size distributions of aerosols in the 60-to-1000-nm range as deployed in situ at ARM sites.

## How it measures

Aerosol particles are drawn into the instrument's optical chamber and pass in front of an infrared (1054-nm) laser beam. The laser illuminates particles, which scatter light, and four optical detectors capture the peak light signals generated by particles passing through the beam, collected in a direction perpendicular to both the particle flow and the laser beam. These signals are used for particle sizing since the amount of light scattered correlates strongly with particle size. The instrument counts particles in up to 100 user-specified sizing bins based on a particle size look-up table relating particle size to pulse height of scattered light, calculated during calibration with monodisperse calibration aerosols (usually PSL).

**Sampling.** reported every every 10 seconds (typical); averaging sample accumulation time is user-defined (hb p. 8).

## Getting the data

ARM Live needs `ARMUSER` / `ARMTOKEN` credentials; see the `act-arm-live` skill for the
service, datastream naming and the server-side subset endpoint.

The `act-arm-live` and `act-qc` skills wrap these calls in shorter helpers
(`armlive_open`, `armlive_list_files`, `act_qc_table`, `act_qc_apply`). Those are helpers
those skills define, **not** ACT functions - nothing below uses them, so every block here
runs against a bare `act-atmos` install.

```python
import os, requests, act

user, token = os.environ["ARMUSER"], os.environ["ARMTOKEN"]

# ACT has no list-only call, so size the request against ARM Live's query endpoint
# before transferring anything.
avail = requests.get("https://adc.arm.gov/armlive/livedata/query",
                     params={"user": f"{user}:{token}", "ds": "enaaosuhsasC1.b1",
                             "start": "2026-09-19", "end": "2026-09-19", "wt": "json"}).json()
print(avail["num_found"], avail["total_size"])            # files, bytes

# Downloads into ./enaaosuhsasC1.b1/ unless you pass output=
files = act.discovery.download_arm_data(user, token, "enaaosuhsasC1.b1", "2026-09-19", "2026-09-19")
assert files, "nothing transferred - ARM Live rate limits with HTTP 429; retry"
ds = act.io.arm.read_arm_netcdf(files, cleanup_qc=True)
print(act.discovery.get_arm_doi("enaaosuhsasC1.b1", "2026-09-19", "2026-09-19"))   # cite what you pulled
```

## Quality control in this datastream

8 `qc_` companion variables cover 8 of the
34 data variables. Assessments present in the example file: `Bad`, `Indeterminate`.

`cleanup_qc=True` on read is what makes these usable - it rewrites ARM's flag
attributes into the form `qcfilter` expects. Remember that ARM uses two assessment vocabularies - `Bad`/`Indeterminate`
from the automated tests, `Incorrect`/`Suspect` after DQR normalisation - and that
filtering on only one of them silently keeps known-bad points.

```python
# What each test would remove, one variable at a time
print(ds["qc_dN_dlogDp"].attrs.get("flag_meanings", "no flag_meanings"))
mask = ds.qcfilter.get_masked_data("dN_dlogDp", rm_assessments=["Bad", "Indeterminate"],
                                  return_mask_only=True)
print(int(mask.sum()), "of", mask.size, "points flagged")

# NaN-fill in place. ARM b1 files use Bad/Indeterminate, VAPs often use
# Incorrect/Suspect - pass every name you might meet.
ds.qcfilter.datafilter(variables=["dN_dlogDp", "total_N_conc", "total_SA_conc"],
                       rm_assessments=["Bad", "Indeterminate", "Incorrect", "Suspect"],
                       del_qc_var=False)
```

Measured on the example file (enaaosuhsasC1.b1.20260919.000006.nc), the tests that fired:

| variable | test | flagged | percent |
|---|---|---|---|
| `sheath_flow_rate` | Value is greater than warn_max | 8640 | 100.0 |
| `purge_flow_rate` | Value is greater than warn_max | 8640 | 100.0 |


A single day is not a quality assessment of the instrument - it shows which tests
are live in this datastream and what a filter would do to the record.

Either way, check the DQRs before trusting a period - they carry the mentor's knowledge
of icing, misalignment and outages that no automated test catches:

```python
try:
    act.qc.print_dqr("enaaosuhsasC1.b1", "20120627", "20260923")
except ValueError:
    print("no DQRs for this window")   # ACT raises rather than returning empty
```

The handbook's own note on data quality: Data quality evaluation involves automatic generation of plots in collaboration with the ARM Data Quality Office: (1) aerosol particle size distribution vs. time, where low counts or noisy signal may indicate optics block issues (misalignment, contamination) or air flow issues (low or unstable sample flow); (2) comparison of particle number concentration from UHSAS vs co-located instruments (CPC or SMPS), where UHSAS should follow the same trend but show lower concentrations due to its higher lower size limit; (3) sample flow rate, where low or unstable flow indicates blockage or failing...

## Known artifacts and failure modes

From the handbook. This is the section to read before concluding that a feature in
the data is atmospheric.

| issue | how it shows up | what the handbook says to do | source |
|---|---|---|---|
| Particle coincidence at high concentrations | Undercounting or sizing errors when total particle counts exceed approximately 3000 s-1 (3600 cm-3 for 50-ccm sample flow); no corrections for particle coincidence are made by the instrument | Use a dilution system when sampling aerosol particles at concentrations higher than the upper limit specified | (hb p. 11) |
| Refractive index mismatch between ambient aerosol and PSL calibration aerosol | Particles with a refractive index different from PSL are misclassified by the instrument; artificial modes can appear in the measured size distributions at particle diameters above ~600 nm | If the particle refractive index is known, corrections can be applied to the measurement data; if unknown (as is the case for most ambient aerosols),... | (hb p. 11) |
| Non-spherical particle shape or refractive index different from PSL calibration aerosol | Ambient aerosol particles can be sized incorrectly | - | (hb p. 10) |
| Optics block misalignment or contamination | Low counts or noisy signal in the aerosol particle size distribution time series | - | (hb p. 9) |
| Air flow issues (low or unstable sample flow) | Low counts or noisy signal in the aerosol particle size distribution; low or unstable sample flow rate readings | - | (hb p. 9) |
| Blockage in sample line or failing pump | Low or unstable sample flow rate | - | (hb p. 10) |
| Dirty optics or misalignment of optical elements | Laser reference voltage more than 25% lower than the nominal value of 2.5V | Clean laser optics when laser reference voltage goes below ~1.9 V | (hb p. 10) |
| Lower particle size detection limit relative to CPC/SMPS | UHSAS total particle number concentration follows the same general trend as CPC/SMPS but shows lower concentrations | - | (hb p. 10) |
| Data object description subject to change | Data field format/content may change with future revisions of instrument software | - | (hb p. 8) |


## Calibration and maintenance

|  |  |
|---|---|
| Calibration method | Measuring the size distribution of NIST-traceable PSL calibration aerosols with known mean particle sizes and calibrating the gain of the four internal pulse-height measurement ranges (light detector electronics responses to aerosols with known particle sizes); calibrating the inlet flow rate with a precision flow... (hb p. 14) |
| Calibration interval | typically once every 12 months or as needed, e.g., before deployment (calibration verification); full calibration performed by manufacturer before delivery and during instrument maintenance (hb p. 14) |
| Traceability | NIST-traceable calibration aerosols (polystyrene latex - PSL) (hb p. 14) |
| Routine maintenance | Cleaning the laser optics (hb p. 14) |
| Maintenance interval | when laser reference voltage goes below ~1.9 V (hb p. 14) |


Calibration history matters for trend work: a step at a calibration date is an
instrument event, not a climate signal.
